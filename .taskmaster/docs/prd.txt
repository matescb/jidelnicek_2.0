# Jídelníček 2.0 - Comprehensive Product Requirements Document
# Part 1: Executive Summary, User Management, and Recipe Core

## Executive Summary

Jídelníček 2.0 is a specialized web application designed for outdoor enthusiasts and expedition leaders to plan, organize, and manage meals for multi-day trips. The application enables precise nutritional planning with automatic ingredient scaling to meet calorie targets, comprehensive tracking of all macro and micronutrients including vitamins, and practical outputs for shopping and packing lists.

### Vision Statement
To become the essential meal planning tool for outdoor expeditions by providing scientifically accurate nutritional calculations, community-driven recipe sharing, and practical expedition management features that ensure adventurers are properly fueled for their journeys.

### Target Users
- **Primary Users**: Long-distance hikers, trail runners, mountaineers, and outdoor enthusiasts planning solo or small group trips
- **Secondary Users**: Scout leaders and expedition organizers managing meals for groups of 5-20 participants on multi-week trips
- **Tertiary Users**: Outdoor guides, adventure companies, and professional expedition planners

### Core Value Propositions
1. **Precision Nutrition Planning**: Automatically scale recipes to meet exact calorie targets per person with 99.9% calculation accuracy
2. **Comprehensive Tracking**: Monitor all macronutrients, micronutrients, vitamins, and special dietary requirements (including PHE for PKU)
3. **Group Management**: Support up to 20 participants with individual coefficient adjustments (10-300%)
4. **Community Marketplace**: Share and discover trail-tested recipes with ratings and reviews
5. **Practical Outputs**: Generate shopping lists, day-by-day packing lists, and fuel calculations
6. **Offline-Ready**: Future PWA support for offline access during expeditions

### Key Features Overview
- Automatic ingredient quantity calculation based on calorie targets
- Recipe versioning with change tracking
- Multi-day trip planning with customizable meal slots
- Participant coefficients for individual portion adjustments
- Recipe marketplace with fork functionality
- Comprehensive nutritional analysis including all vitamins
- Fuel requirement calculations based on stove efficiency
- Export to PDF, Excel, and text formats
- Share links for trips and recipes with expiration control
- Dual rating system (personal vs marketplace)
- Multi-language support (English and Czech)

### Technical Overview
- **Architecture**: Modular monolith with clear module boundaries, ready for future microservices migration
- **Deployment**: Single VPS (vpsFree.cz) optimized for 100 concurrent users
- **Backend**: Python 3.11+ with FastAPI, SQLAlchemy 2.0, PostgreSQL 15
- **Frontend**: Next.js 14 with React 18, TypeScript, Tailwind CSS + Shadcn/ui
- **Performance**: <3s page loads, <200ms API responses, 99.9% calculation accuracy
- **Security**: JWT authentication, OAuth2, optional 2FA, comprehensive input validation
- **Scalability**: Designed for 100 users on 4GB VPS with clear upgrade path

### Success Metrics
- **Launch Goals (3 months)**: 50 registered users, 50 active trips, <2% critical bugs
- **Year One Goals**: 100 users, 50% MAU, 100+ marketplace recipes, NPS >50
- **Performance**: 95% uptime, <200ms API response time, 99.9% calculation accuracy
- **Quality**: >80% test coverage, <5 user-reported bugs/month

## 1. User Management System

### 1.1 Authentication and Account Creation
**Priority: Critical - Phase 1**
**User Story Reference: US-1**

#### 1.1.1 Registration Requirements

User registration with comprehensive security:
- **Email Address**: 
  - Valid RFC 5322 format
  - Maximum 255 characters
  - Must be unique in system
  - Case-insensitive matching
  - Verification required before activation
  - Error: "Please enter a valid email address" / "Email must not exceed 255 characters" / "An account with this email already exists"

- **Password Requirements**:
  - Minimum 12 characters, maximum 128 characters
  - Must contain at least one uppercase letter (A-Z)
  - Must contain at least one lowercase letter (a-z)
  - Must contain at least one number (0-9)
  - Must contain at least one special character (!@#$%^&*()_+-=[]{}|;:,.<>?)
  - Cannot contain the email address or username
  - Stored using bcrypt with cost factor 12
  - Password strength indicator during entry
  - Common password check against top 10,000 list
  - Error messages:
    - "Password must be at least 12 characters long"
    - "Password must contain at least one uppercase letter"
    - "Password must contain at least one lowercase letter"
    - "Password must contain at least one number"
    - "Password must contain at least one special character (!@#$%^&*)"
    - "Password must not exceed 128 characters"
    - "Password cannot contain your email address"
    - "This password is too common. Please choose a more unique password"

- **Email Verification**:
  - Verification link sent immediately upon registration
  - Token expires in 24 hours
  - Unique, cryptographically secure token
  - One-time use only
  - Resend option available (max 3 per hour)
  - Clear instructions in email
  - Error: "Verification link has expired" / "Invalid verification token"

#### 1.1.2 Login and Session Management

Secure authentication flow:
- **Login Process**:
  - Email and password validation
  - Case-insensitive email matching
  - Timing-safe password comparison
  - Session fingerprinting (IP + User-Agent hash)
  - Account lockout after 5 failed attempts
  - Progressive delays: 5 min, 15 min, 1 hour
  - CAPTCHA after 3 failed attempts
  - Clear error messages without revealing account existence
  - Error: "Invalid email or password" (generic for security)

- **Session Management**:
  - JWT tokens with 24-hour expiration
  - Refresh tokens with 7-day expiration
  - HTTP-only, secure, sameSite cookies
  - Token rotation on refresh
  - Maximum 5 concurrent sessions per user
  - Session timeout after 24 hours of inactivity
  - Automatic session cleanup for expired tokens
  - Device management view for users

- **OAuth2 Integration**:
  - Google OAuth2 with email scope
  - Facebook OAuth2 with email scope
  - Account linking for existing emails
  - Profile data synchronization options
  - Secure state parameter for CSRF protection
  - Clear consent screen information

#### 1.1.3 Password Reset Flow

Secure password recovery:
- **Reset Request**:
  - Email input with format validation
  - Rate limiting: 3 requests per hour per email
  - Success message regardless of email existence
  - Token generation for valid accounts
  - 1-hour expiration for reset tokens
  - Secure random token generation
  - Email with clear instructions
  - Error: "Too many password reset attempts. Please try again later"

- **Reset Completion**:
  - Token validation with expiration check
  - New password with full validation rules
  - Immediate invalidation of all existing sessions
  - Email notification of password change
  - Token single-use enforcement
  - IP address logging for security
  - Error: "Password reset link has expired" / "Invalid reset token"

#### 1.1.4 Two-Factor Authentication (Phase 1.1 Post-MVP)

Enhanced security with 2FA:
- **TOTP Implementation**:
  - Time-based One-Time Password (RFC 6238)
  - 30-second time window
  - QR code for easy setup
  - Manual key entry option
  - Compatible with standard authenticator apps
  - 6-digit numeric codes
  - Error: "Invalid authenticator code. Please check your device time is synchronized"

- **Recovery Codes**:
  - Exactly 8 recovery codes generated
  - 10-character alphanumeric format
  - Single-use only
  - Secure display with download option
  - Regeneration requires current password
  - Used codes marked as consumed
  - Warning when only 2 codes remain
  - Error: "Invalid recovery code" / "This recovery code has already been used"

- **2FA Management**:
  - Optional for regular users
  - Mandatory for administrators
  - Backup verification method required
  - 2FA bypass requires email verification
  - Session elevation for sensitive operations
  - Clear setup wizard with testing

## 2. Recipe Management System

### 2.1 Recipe Creation and Editing
**Priority: Critical - Phase 1**
**User Story Reference: US-2**

#### 2.1.1 Recipe Basic Information

Core recipe details with validation:

- **Recipe Name**:
  - Required field
  - Length: 1-100 characters
  - Allowed characters: letters, numbers, spaces, . , ' - ( )
  - No special characters or emojis
  - Must be unique per user
  - Case-insensitive uniqueness check
  - Validation: regex ^[\w\s\.\,'\-\(\)]{1,100}$
  - Error: "Recipe name is required and must be between 1-100 characters"
  - Error: "Recipe name contains invalid characters"
  - Error: "You already have a recipe with this name"

- **Recipe Description**:
  - Optional field
  - Maximum 500 characters
  - Plain text only (HTML stripped)
  - Line breaks preserved
  - Used in marketplace search
  - Error: "Description must not exceed 500 characters"

- **Preparation Instructions**:
  - Required field
  - Maximum 2000 characters
  - Markdown support (limited subset)
  - Allowed tags: p, br, strong, em, ul, ol, li
  - Auto-linkification of URLs
  - Strip all JavaScript and event handlers
  - Validation with bleach library
  - Error: "Instructions are required"
  - Error: "Instructions must not exceed 2000 characters"
  - Error: "Instructions contain invalid HTML tags"

- **Category Selection**:
  - Required field
  - Single selection from predefined list:
    - Breakfast (Hot, Cold, Quick Start)
    - Main Meals (Lunch, Dinner, One-Pot)
    - Snacks (Trail, Energy Bars, Quick Bites)
    - Beverages (Hot, Cold, Recovery)
    - Desserts
    - Special Dietary
  - Used for marketplace organization
  - Error: "Please select a category"

- **Tags**:
  - Optional, multiple selection
  - Maximum 10 tags per recipe
  - Tag length: 1-30 characters
  - Predefined tags + custom tags
  - Common tags: vegetarian, vegan, gluten-free, dairy-free, nut-free, high-protein, low-carb, no-cook, lightweight, PKU-friendly
  - Used for search and filtering
  - Error: "Maximum 10 tags allowed"
  - Error: "Tag must be between 1-30 characters"

#### 2.1.2 Time and Servings

Recipe preparation metrics:

- **Preparation Time**:
  - Required field
  - Range: 0-1440 minutes (24 hours)
  - Input as minutes
  - Display as hours:minutes
  - Includes all prep work
  - Error: "Prep time must be between 0-1440 minutes (24 hours)"

- **Cooking Time**:
  - Required field
  - Range: 0-1440 minutes (24 hours)
  - Excludes water boiling time
  - Active stove time only
  - Used for fuel calculations
  - Error: "Cook time must be between 0-1440 minutes (24 hours)"

- **Total Time Validation**:
  - prep_time + cook_time ≤ 1440 minutes
  - Error: "Total cooking time cannot exceed 24 hours"

- **Servings**:
  - Required field
  - Range: 1-100
  - Integer only
  - Base for scaling calculations
  - Default: 4 servings
  - Error: "Servings must be between 1-100"

- **Water Requirements**:
  - Required field for cooking
  - Range: 0-10000 ml
  - Cooking water only (not drinking)
  - Used for fuel calculations
  - Separate from ingredient water
  - Error: "Water amount must be between 0-10000 ml"

Comprehensive ingredient system:

- **Ingredient Selection**:

  - Create new ingredient inline
  - Maximum 50 ingredients per recipe
  - Drag-and-drop reordering
  - Grouping by category option

  - Smart unit suggestions based on amount
  - Running nutritional total display

- **Ingredient Validation**:
  - No duplicate ingredients

  - Calorie density indicator

def validate_macronutrients(data):
    """Validate macronutrient consistency"""
    errors = []
    
    # All values per 100g
    proteins = data.get('proteins', 0)
    carbs = data.get('carbohydrates', 0)
    fats = data.get('fats', 0)
    sugars = data.get('sugars', 0)
    saturated = data.get('saturated_fats', 0)
    fiber = data.get('fiber', 0)
    water = data.get('water', 0)
    
    # Basic range validation
    if not 0 <= proteins <= 100:
        errors.append("Proteins must be between 0-100g per 100g")
    
    if not 0 <= carbs <= 100:
        errors.append("Carbohydrates must be between 0-100g per 100g")
        
    if not 0 <= fats <= 100:
        errors.append("Fats must be between 0-100g per 100g")
    
    # Cross-field validation
    if sugars > carbs:
        errors.append("Sugars cannot exceed total carbohydrates")
        
    if saturated > fats:
        errors.append("Saturated fats cannot exceed total fats")
        
    if fiber > carbs:
        errors.append("Fiber cannot exceed total carbohydrates")
    
    # Dry weight validation (excluding water)
    dry_weight = proteins + carbs + fats
    if not 0.95 <= dry_weight / (100 - water) <= 1.05:
        errors.append("Macronutrient sum seems incorrect for dry weight")
    
    # Calorie calculation check
    calculated_calories = (proteins * 4) + (carbs * 4) + (fats * 9)
    stated_calories = data.get('calories', 0)
    if abs(calculated_calories - stated_calories) > stated_calories * 0.1:
        errors.append("Calorie value doesn't match macronutrient calculation")
    
    return errors
```

        errors.append(f"Cannot process more than {BATCH_CONSTRAINTS['max_items']} items in a single operation")
    
    if operation not in BATCH_CONSTRAINTS["operations"]:
        errors.append(f"Invalid batch operation: {operation}")
    
    return errors
```

RATE_LIMITS = {
    # Format: (requests, window_seconds)
    "/api/auth/login": (5, 900),          # 5 per 15 minutes
    "/api/auth/reset": (3, 3600),         # 3 per hour
    "/api/recipes": (1000, 3600),         # 1000 per hour

    "/api/upload": (10, 3600),            # 10 per hour
    "default_authenticated": (1000, 3600), # 1000 per hour
    "default_anonymous": (100, 3600)       # 100 per hour
}

def check_rate_limit(endpoint, user_id, ip_address):
    """Check if request exceeds rate limit"""
    key = f"{endpoint}:{user_id or ip_address}"
    limit, window = RATE_LIMITS.get(endpoint, RATE_LIMITS["default_authenticated"])
    
    current_count = get_request_count(key, window)
    if current_count >= limit:
        return True, "Rate limit exceeded. Please try again later"
    
    increment_request_count(key, window)
    return False, None

```python
PRECISION_RULES = {
    "weight": {
        "display_decimals": 1,
        "storage_decimals": 2,
        "unit": "g",
        "example": "100.0g"
    },
    "calories": {
        "display_decimals": 0,
        "storage_decimals": 2,
        "unit": "kcal",
        "example": "365 kcal"
    },
    "macronutrients": {
        "display_decimals": 1,
        "storage_decimals": 2,
        "unit": "g",
        "example": "24.3g"
    },
    "micronutrients": {
        "display_decimals": 2,
        "storage_decimals": 3,
        "unit": "mg",
        "example": "1.25mg",
        "small_value": "<0.01"
    },
    "percentage": {
        "display_decimals": 0,
        "storage_decimals": 2,
        "unit": "%",
        "example": "45%"
    },
    "currency": {
        "display_decimals": 2,
        "storage_decimals": 2,
        "unit": "$",
        "example": "$12.99"
    }
}

def format_nutritional_value(value, nutrient_type):
    """Format nutritional values for display"""
    if nutrient_type not in PRECISION_RULES:
        return str(value)
    
    rules = PRECISION_RULES[nutrient_type]
    
    # Handle very small values
    if nutrient_type == "micronutrients" and value < 0.01:
        return rules["small_value"]
    
    # Format with appropriate decimals
    format_str = f"{{:.{rules['display_decimals']}f}}"
    formatted = format_str.format(value)
    
    # Add unit if specified
    if "unit" in rules:
        formatted += rules["unit"]
    
    return formatted
